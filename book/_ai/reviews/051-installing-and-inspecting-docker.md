## Material findings

1. **Medium — lines 84–91, verification command block: missing access prerequisite and changed identity.** The preceding procedure explicitly uses `sudo`, and neither installs rootless Docker nor grants group membership. On the fresh rootful host described here, plain `docker version` cannot retrieve the server and `docker info` fails with socket permission denial. This is an expected consequence of the procedure, not evidence of a broken installation. Show verification under the same privileged identity with its own context inspection, then separately explain how an authorized ordinary user verifies their target. Do not quietly grant group membership to fix the example. Docker's [post-installation instructions](https://docs.docker.com/engine/install/linux-postinstall/) confirm users are not added automatically and socket access requires suitable authority.

2. **Medium — lines 87–93, target verification: endpoint overrides omitted.** The prose says context inspection identifies the active target but never checks `DOCKER_HOST`, `DOCKER_CONTEXT`, `DOCKER_CONFIG` or explicit `--host`/`--context` selection. Especially across `sudo`, the CLI configuration and environment may differ. A stored context endpoint is insufficient evidence when an endpoint override is present. Explain override precedence and include a read-only check of relevant variables/configuration for the identity running the command; use a consistent explicit target in the local installation check. Docker's [context guide](https://docs.docker.com/engine/manage-resources/contexts/) documents environment and global-option overrides, while [`context show`](https://docs.docker.com/reference/cli/docker/context/show/) names a context rather than proving a successful connection.

3. **Medium — lines 75–78, failure diagnosis loses evidence.** `--rm` automatically removes a container after exit, so the instruction to inspect its exit status and logs needs a concrete evidence-preservation path. Explain that the initial foreground output and immediate shell exit status are available, and show a named retry without `--rm` followed by inspect/log commands and cleanup when retained container evidence is required. Explain `--rm` beside its first use. The [`run` reference](https://docs.docker.com/reference/cli/docker/container/run/) documents automatic removal.

4. **Medium — lines 97–107 and cross-references at 64/70/93: assessment and navigation contract incomplete.** All five assessment items are questions; there is no practical exercise with answer/evidence guidance, no explicit takeaways, and no relative links to the prerequisite or numbered canonical chapters. Add one bounded installation/inspection exercise with expected evidence and diagnosis guidance, concise answer guidance, takeaways and navigable prerequisite/canonical links. This is required by `AI_AUTHORING_GUIDE.md` and the chapter's skeleton brief. The existing concise narrative is readable and avoids substantial repetition, so these additions should remain focused.
